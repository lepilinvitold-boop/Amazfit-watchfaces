# Порядок разработки циферблатов Витольда

Прочитать до любых изменений. Принятая основа «Графит-арм» — 1.0.9, ветка graphite-arm-1.0.9, projects/Graphite-Arm-1.0.9. Старые экспериментальные версии не использовать. Другие семейства проектов сохранять отдельно.

## До правок

1. Найти последнюю принятую версию и реальный скриншот пользователя. Зафиксировать входные файлы, appId, версию и SHA256 ZPK. Прочитать build.py, watchface.js, validate.cjs, check_layout.py.
2. Составить список запрошенных изменений и неизменяемых элементов. Не заменять стрелки, шрифты, иконки и безель по собственной инициативе. Если нужен только острый кончик, менять лишь кончик, строго по продольной оси.
3. Уточнять только недостающие сведения. Исправлять весь согласованный список до выдачи новой сборки. Не выпускать промежуточные опыты как законченные версии.

## Геометрия: сначала числа, затем рисунок

- Система координат 480×480, ось (240,240). Центры кругов (240,110), (110,240), (370,240), (240,370), расстояние от оси 130, радиус внешнего кольца 65.
- Чёрная область погоды радиусом около 50. Размеры основных цифр всех четырёх кругов одинаковы, номинально 30. Проверять ширину 10000 и 99999 шагов, а не только 4646.
- Подписи шкал: общий центр вращения (240,240), радиус 159. Нельзя сдвигать всю группу вверх: это сближает верхние подписи со шкалами и отдаляет нижние. Для равных отступов менять радиус одинаково во всех четырёх секторах.
- Цифры шкал 25, знак процента 24; межбуквенный угловой шаг 5.2°. Проценты у батареи, шагов и калорий; пульс без процента. Значков возле шкал нет.
- Секторы: батарея 290–335°, пульс 25–70°, шаги 205–250°, калории 110–155°. Одинаковую видимую длину проверять с учётом ширины крайних полосок и круглых маркеров. Одинаковый угол сам по себе её не гарантирует.
- Все четыре шкалы начинают заполнение со стороны своего круга. Калории идут снизу вверх. Для сегментных шкал пульса/шагов начинать с последнего углового сегмента.
- В каждом кадре генерации восстанавливать start/end сектора. Не накапливать поправки к углам внутри цикла уровней.
- Подложка и её выемки симметричны. Рамки кругов, перемычки, контактные тени и светлый внутренний кант безеля сохраняют объём; ничего не должно заходить на минутные деления.

## Погода, дата и время

- Мин./макс.: y381, цифры 25 с шириной 10, градус шириной 6, отрицательный знак шириной 7, h_space=-1. Минимум выравнивается вправо в x195,w38; максимум влево в x247,w38. Тире x235,y386,width10.
- Проверять каждый результат от −99 до +99 на каждой стороне, включая знак, градус и тире; пиксели не пересекают чёрную область радиуса50 и соседние элементы.
- Время HH:MM:SS под верхним кругом, дата ниже оси над погодой; серебристые изогнутые рамки. Текст по дуге должен читаться слева направо.
- Для динамических изображений менять SRC отдельным вызовом. В прежней реализации дата не обновлялась через SRC внутри MORE. Проверять именно упакованный JS и ресурсы.
- В AOD время HH:MM, секундной стрелки нет; полный приглушённый циферблат. Активная секунда — IMG с дробным углом, таймер50мс. Останавливать таймер при pause/destroy, восстанавливать при resume. Модель не доказывает плавность на физических часах.

| Место | Действие |

| Шкала батареи | Нативный IMG_CLICK BATTERY |
| Круг шагов | Нативный IMG_CLICK STEP |
| Нижняя левая шкала | Нативный IMG_CLICK DISTANCE |
| Нижняя правая шкала | Нативный IMG_CLICK CAL |
| Круг пульса | heart_app_Screen |
| Круг погоды | WeatherScreen |
| Дата | ScheduleCalScreen |
| Левая часть рамки времени | AlarmInfoScreen |
| Середина рамки времени | StopWatchScreen |
| Правая часть рамки времени | CountdownAppScreen |

Шкалы имеют составные прямоугольные зоны; всего18 виджетов нажатия. Прозрачный PNG не делает прямоугольную зону круглой. Проверять реальные координаты и отсутствие перекрытий, включая центр, соседние круги, края и концы шкал. Не заменять DISTANCE/CAL общей страницей активности, если нужен соответствующий показатель. В AOD интерактивные зоны отключены.

## Обязательная проверка до выдачи

1. Запустить build.py; дождаться завершения. Запустить node validate.cjs verify-graphite-arm-109 и python3 check_layout.py из корня репозитория, обновляя путь только при новой версии.
2. Проверять каждый кадр всех21 уровней четырёх шкал; отступы до кругов, времени, даты и безеля. Прогнать длинные подписи 100%,150%,9999%,255 и отсутствующие данные. Сверять геометрию preview с реальными center/pos/angle виджетов.
3. Проверить смену времени/даты, полночь, год, русские дни недели, заряд0/100, пульс отсутствует/восстановлен, достижение и превышение целей, погоду с минусами.
4. Проверить normal/AOD, очистку listeners/timer, повторный build, скрытие/возврат стрелок, все назначения тапов в конечном пакете.
5. Визуально открыть обычное превью и AOD. Не считать отсутствие ошибки в скрипте доказательством красоты или отсутствия пересечения. Не выдавать синтетическое превью за скриншот часов.
6. Проверить appId: обновление сохраняет10623141; отдельный проект требует другого appId. Увеличивать versionCode, сохранять русский интерфейс.
7. Публиковать только проверенный ZPK; сверить удалённый ZPK с локальным побайтно, проверить QR и его ссылку. Проверки на часах явно отделять от модельных тестов.
8. После принятия обновлять эту инструкцию и README проекта. Финальный результат: версия, QR, краткие изменения и реально оставшиеся ограничения.
